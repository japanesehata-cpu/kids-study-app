# プロダクト要求定義書（PRD）

## 1. 概要
- プロダクト名：まなびフレンズ（Manabi Friends）／リポジトリ名 `kids-study-app`
- 一言で言うと：親のスマホにインストールして子どもに渡す、キャラクターと一緒に遊びながら学べる学習アプリ（PWA）。算数と英語だけでなく、ことば（文字・漢字）と考える力（論理・観察）も養う。子どもが「またやりたい」と言い出したくなることを目指す。

## 2. 背景と課題
- 市販の学習アプリは、広告や課金への誘導がある、内容が子どもの今のレベルに合わない、すぐ飽きる、といった問題がある。
- ドリルや紙の教材は、子どもが自分から手に取るまでに親の声かけが必要になる。
- そこで、自分の子どもの興味とレベルに合わせて内容を作り込める、家庭専用のアプリを自作する。中身（問題・イラスト・音声・演出）は子どもの反応を見ながら継続的に足していく。

## 3. 対象ユーザー
| ペルソナ | 特徴 | 主なニーズ |
|---|---|---|
| 子ども（主ユーザー） | 開発者自身の子ども1人。未就学〜小学校低学年。文字はひらがなが読める程度で、長い文は読めない。自分の端末は持たず、親のスマホを渡されて使う | 文字を読まなくても遊べる（音声・絵・キャラクター）。すぐ褒められる。短時間で区切りがつく |
| 親（副ユーザー・開発者） | アプリの開発・運用者でもある。自分のスマホにアプリを入れ、起動して子どもに渡す | 子どもが1人で操作を完結できる。どこまでできるようになったかを確認できる。子どもに設定を勝手に変えられない |

## 4. 目的とゴール
- プロダクトのゴール：子どもが**自分から「やりたい」と言い出したくなり、飽きずに、継続して学習できる**こと。アプリは親のスマホに入っており子どもが自分で起動することはないため、「自発性」は子どもが親にアプリを求めることで表れる。
- 成功指標（KPI）：外部への送信をしない方針のため（[7. スコープ外](#7-スコープ外やらないこと)）、計測は端末内の学習記録（進み具合の画面）と親の観察で行う。
  - 自発性：親が声をかけずに、子どもが自分から「やりたい」と求めた日が、週 TBD 日以上。
  - 継続：学習した日が TBD 週連続で途切れない。
  - 飽きにくさ：1回の利用で TBD 問（セット）以上を、途中でやめずに終えられる。
  - 上達：各カテゴリで、子どもが到達レベルを1つ以上上げていく。

## 5. 機能要件
| ID | 機能 | 説明 | 優先度（Must/Should/Could） |
|---|---|---|---|
| F-01 | ホームとカテゴリ選択 | 学習カテゴリをカードで選ぶ。キャラクターの挨拶、言語切替、BGM のオン・オフ、保護者ゲートへの入口を持つ | Must |
| F-02 | レベル選択 | カテゴリごとに★レベルと1セットの問題数を選ぶ。各レベルに「何ができるようになるか」の短い説明を出す | Must |
| F-03 | クイズ出題と回答 | 選択式・数字入力・タップなど、カテゴリに合った形式で1セット分出題し、正誤を判定する | Must |
| F-04 | 算数カテゴリ | たしざん・ひきざん（文章題を含む）、□を求める問題、とけい、おかね、かぞえる（助数詞） | Must |
| F-05 | ことばカテゴリ | ひらがな・カタカナ・アルファベット・漢字（1〜2年）の読みと書き、えいご（単語・リスニング） | Must |
| F-06 | 考える力カテゴリ | ろんり（なかまはずれ・きまり・くらべる・はんたいことば）、まちがいさがし、すうどく | Must |
| F-07 | なぞり書き・手書き | 文字を指でなぞる／書く練習。書き順に沿っているかを判定する | Must |
| F-08 | 音声読み上げ | 問題文・選択肢・正解・ほめ言葉を音声で読み上げ、文字を読めなくても進められるようにする | Must |
| F-09 | 正解・不正解の演出 | 正解時ははなまる・紙吹雪・効果音・連続正解の表示で褒める。不正解時も責めない優しい表現にする | Must |
| F-10 | 結果画面 | 1セット終了時に★の数と結果を出し、ごほうびの演出をする | Must |
| F-11 | 学習記録 | カテゴリごとの到達レベルと成績を端末内に保存し、次回も続きから遊べる | Must |
| F-12 | 保護者ゲートと進み具合 | 子どもには解けない計算で保護する保護者向け画面から、学習の進み具合を確認する。親のスマホを渡して使うため、子どもが設定や記録を変えられないようにする | Should |
| F-13 | キャラクターと没入演出 | カテゴリごとの案内キャラクター（まばたき・ゆれ）、画面切替のエフェクト、タップ時のきらめき、BGM | Should |
| F-14 | 日本語・英語の表示切替 | 画面表示を日本語と英語で切り替える | Should |
| F-15 | オフライン利用・ホーム画面追加 | 一度開けば通信がなくても遊べ、端末のホーム画面にアプリとして追加できる | Should |

### ユーザーストーリー
- 子どもとして、文字が読めなくても音声とキャラクターの案内だけで問題に答えたい。なぜなら、まだ長い文を読めないから。
- 子どもとして、正解したらすぐに大きく褒めてもらいたい。なぜなら、褒められるともっとやりたくなるから。
- 子どもとして、簡単すぎず難しすぎないレベルを自分で選びたい。なぜなら、ちょうどいい難しさのときに一番楽しいから。
- 子どもとして、毎回少し違う問題や絵に出会いたい。なぜなら、同じ問題の繰り返しだと飽きるから。
- 親として、子どもがどこまでできるようになったかを確認したい。なぜなら、次に何を足せばいいかを決めたいから。
- 親として、子どもに設定や記録を勝手に変えられたくない。なぜなら、子どもが1人で使うから。

## 6. 非機能要件
- 性能：タップへの反応（押した見た目・効果音）は即座に返す。正解演出は約1.5秒以内に終わり、次の操作を待たせない。
- 可用性：静的ホスティング（GitHub Pages）で配信し、一度読み込んだ後はオフラインでも全機能が動く。
- セキュリティ・プライバシー：学習記録・設定は端末内（localStorage）にのみ保存し、外部へ送信しない。ログイン・個人情報の入力はない。
- アクセシビリティ：文字を読めない子どもでも使えるよう、主要な情報は音声と絵でも伝える。タップ対象は子どもの指で押せる大きさにする。端末の「視差効果を減らす」設定では大きな動きを抑える。
- 対応環境（ブラウザ・OS・端末）：親のスマートフォンの**縦画面に特化**する（ホーム画面に追加した PWA）。横画面・タブレット・PCは、縦画面のレイアウトをそのまま表示できれば足り、専用のレイアウトは作らない。iOS Safari（ホーム画面追加を含む）と Chrome に対応する。どの画面もスクロールなしで1画面に収める。

## 7. スコープ外（やらないこと）
- アカウント登録・ログイン・サーバー側での保存・端末間の同期
- 広告の表示、アプリ内課金
- 学習記録や利用状況など、データの外部への送信（アクセス解析を含む）
- App Store／Google Play でのストア配信（PWA のみで提供する）
- 複数の子どもや一般ユーザー向けの機能（ユーザー切替など）

## 8. 制約・前提条件
- 体制：開発者（親）1人と AI アシスタントで開発・運用する。
- 予算：ランニングコストは無料の範囲（GitHub Pages）に収める。イラスト・音声などの素材は開発時に生成してリポジトリに含め、実行時に有料 API を呼ばない。
- 技術的制約：サーバーを持たない静的サイトであること。詳細は [architecture.md](./architecture.md) を参照。
